# Step 5 Security and Production Readiness Review

**Review status:** Pre-production review only. This document is not an independent audit, penetration test, legal opinion, or production approval.

## Controls present

- NestJS uses Helmet, strict request validation, configured CORS, a global request limit, and default-deny authentication guards for non-public routes.
- Market and Solana RPC routes are explicitly public and pass through the global rate limiter. The RPC proxy restricts JSON-RPC methods, limits batches, hides provider URLs, and never retries `sendTransaction`.
- Devnet transaction relay is opt-in, limited to Devnet by environment validation, and checks the Devnet genesis hash before submission. Mainnet transaction relay is rejected.
- The web client requires wallet signatures for PREDICT state changes. Swap output is taken from an unsigned Devnet transaction simulation, refreshed before signing, then bounded by the user-selected on-chain minimum output.
- Prisma uses parameterized client operations; no raw SQL or user-controlled backend URL fetch was identified in the reviewed application paths.
- A GitHub Actions verification workflow now runs lint, tests, and production builds on pushes to `main` and pull requests.

## Release blockers

1. **Identity and authorization are not operational.** The guard rejects protected requests because no identity provider, signature-verification flow, session, or token validation is configured. Do not add user-specific endpoints until authentication, authorization, CSRF/session handling, and audit coverage are implemented and tested.
2. **No jurisdiction or eligibility controls exist.** There is no geographic restriction, age/account eligibility, KYC/AML or sanctions integration, market-category policy, or responsible-trading control. Obtain jurisdiction-specific legal/compliance review and implement the required controls before offering access.
3. **No production trading integration or reconciliation exists.** Polymarket is read-only; PREDICT is Devnet-only; positions, orders, settlement, and cross-venue accounting are not verified. Do not represent this build as a production trading platform.
4. **External protocol risk remains.** PREDICT has not received an independent audit according to its own documentation and has centralized resolution and upgrade-authority risks. Obtain an independent review before any Mainnet use; this repository does not deploy or audit that program.
5. **Production infrastructure is not provisioned.** No production database/Redis, secret store, backups, restore test, monitoring/alerting, error tracking, incident-response procedure, rollback exercise, or load/reliability evidence is configured.
6. **Solana providers are unconfigured.** RPC URLs remain placeholders. Devnet relay is disabled by default. Do not enable Mainnet transactions; no Mainnet relay exists.
7. **Web/API split must be configured.** Vercel deploys the Next.js web app only. Deploy the NestJS API separately and set `NEXT_PUBLIC_API_URL` to its HTTPS origin, and set the API `WEB_ORIGIN` to the exact deployed web origin. Localhost is a development-only default; production uses a reserved `.invalid` placeholder until configured, so visitor browsers never send requests to their own local machine.
8. **Dependency vulnerability status is unknown.** `pnpm audit --prod` could not reach the npm advisory endpoint in this environment (EACCES); rerun dependency scanning in CI or another network-enabled environment and review advisories before release.

## Security notes and follow-up

- The throttler uses process-local state; it is not a distributed rate limit across replicas. Use a shared gateway or Redis-backed limiter before scaling public endpoints.
- Public RPC and market reads can still consume provider quota. Configure provider-side limits, request-size limits, alerts, and abuse monitoring before production.
- CORS is restricted to the configured `WEB_ORIGIN`, but deployments must set it explicitly. Do not use wildcard origins with credentialed requests.
- No production secret values belong in this repository. Use the hosting platform's secret manager and rotate provider credentials if they have ever been committed elsewhere.
- `docker-compose.yml` credentials are local-development defaults only; never reuse them in a hosted environment.
- Run the PREDICT and Solana transaction failure scenarios from the project specification against Devnet, including stale quotes, duplicate submissions, partial/failed transactions, pool changes, and reconciliation. No Mainnet tests are authorized or required for this pre-production review.

## Deployment configuration

The root `vercel.json` selects the Next.js workspace build and the production artifact directory generated by `apps/web/next.config.ts`. In the Vercel project, use the repository root (`.`) as **Root Directory** so the root configuration and pnpm workspace are available. Set `NEXT_PUBLIC_API_URL` in Vercel to the separately deployed API origin. Redeploy after applying these settings; the repository cannot change the existing Vercel project's dashboard configuration directly.

## Go-live decision

**Not approved for production trading or Mainnet.** The current code is suitable only for development/Devnet and a web preview backed by an independently configured API. Reassess each blocker above with evidence before controlled rollout.
